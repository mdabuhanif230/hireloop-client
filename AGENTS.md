# hireloop-client

Single-package Next.js 16.4.4 (App Router) + React 19 + Tailwind v4 + shadcn/ui. No workspace/monorepo, **no tests, no CI, no test runner** — don't look for one.

## Commands

- **`npm` fails in PowerShell here** (`npm.ps1` blocked by execution policy). Always use **`npm.cmd run …`**.
- Dev server: `npm.cmd run dev` · Build: `npm.cmd run build`
- Verification order: `npm.cmd run typecheck` → `npm.cmd run lint`. Both pass clean at baseline (2026-11); a failing run means you broke something.
- `npm.cmd run format` runs Prettier over `**/*.{ts,tsx}` only (`.prettierrc`: **no semicolons, double quotes, LF**, `prettier-plugin-tailwindcss` re-sorts Tailwind classes). Match that style by hand when not running it.
- `git config core.autocrlf=true` and there is no `.gitattributes`, so git prints LF→CRLF warnings. Ignore them; don't rewrite line endings.

## Where things live

- `app/layout.tsx` — root: fonts, `ThemeProvider`, `Navbar`, `suppressHydrationWarning`. `app/page.tsx` renders `components/hero.tsx` (the dark `#010103` Figma hero is the whole homepage for now).
- `components/*.tsx` = feature components (`navbar`, `hero`, `theme-provider`); `components/ui/*` = generated shadcn primitives. `hooks/` and `lib/` are mostly stubs.
- `@/*` maps to the repo root (`tsconfig.json` paths).

## Quirks you would otherwise get wrong

- **Tailwind v4 has no config file.** Theme tokens live in `app/globals.css` under `@theme inline`. A `next/font` font only becomes usable if it's declared **twice**: as a `variable` in `app/layout.tsx` *and* as `--font-<name>` in `@theme inline` — otherwise `font-*` utilities silently do nothing. Satoshi is self-hosted via `@font-face` in `globals.css` (Fontshare, not Google).
- **shadcn style is `base-nova`: primitives come from `@base-ui/react`, not Radix.** `components.json` is the source of truth — add components with `npx shadcn@latest add <name>`; hand-written Radix code will not fit.
- `cn` is imported two ways in this repo and both are valid: `@/lib/utils` (re-export) and directly from the `cn` package.
- **Static assets: `public/` is the web root.** Write `src="/images/logo.png"`, never `./public/images/logo.png` (that 404s). Company logos are in `public/logos/`.
- `next.config.ts` sets `dangerouslyAllowSVG` so `/public` SVGs work through `next/image` — keep it if you add more.
- **Don't remove `suppressHydrationWarning` from `<body>`** in `app/layout.tsx`. Browser extensions inject attributes (e.g. `cz-shortcut-listen`) into `<body>` before React hydrates; the attribute does not cascade from `<html>`, so dropping it reintroduces a hydration error.
- Theming: `next-themes` with `attribute="class"`, default `system`; `d` key toggles dark/light (`components/theme-provider.tsx`).
- `AGENTS.md`'s leading block and `CLAUDE.md` (which is just `@AGENTS.md`) are regenerated by `next dev`. Commit them with your work instead of reverting them.

## Auth (better-auth) — current state

- `lib/auth.ts` → `betterAuth` + `mongodbAdapter`, db `hireloopdb`. The Mongo URI comes from `BETTER_AUTH_MONGODB_URL` in `.env` (gitignored) and **falls back to `mongodb://localhost:27017`** so a missing var doesn't throw at import time.
- Google social login reads `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`, which are **not** in `.env` — only `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL` and `BETTER_AUTH_MONGODB_URL` are. Set the credentials in each environment yourself; until then better-auth logs `CLIENT_ID_AND_SECRET_REQUIRED` and the Google button errors.
- Route handler: `app/api/auth/[...all]/route.ts` exports `GET`/`POST` via `toNextJsHandler`.
- `lib/auth-client.ts` creates **one** client and re-exports `signIn`/`signUp`/`useSession` from it. Keep it that way: better-auth builds a fresh session atom per `createAuthClient()`, so a second instance never learns about a sign-in done through the first — the navbar would stay stuck on "Sign In".
- Session-aware UI lives in `components/navbar.tsx` (`authClient.useSession()` → placeholder while pending, name + Sign out when signed in). Both auth forms call `router.replace("/")` on an existing session so a signed-in user can't sit on `/sign-in`.
